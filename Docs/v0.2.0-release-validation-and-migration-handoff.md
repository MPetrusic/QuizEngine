## Consumer migration handoff

1. Pin the intended exact package release; do not use a branch or local path in a shipping app. AmericanQuiz remains pinned to exact `v0.1.3` until its Phase 3 content, variant, and migration cutover is approved.
2. Build one validated `QuizVariantDefinition`, one `QuestionDataService`, and one shared `PlayerProgressManager`. Every session must use that same variant and question service.
3. Decode the configured resource and call `QuizContentValidator.validate(_:categories:)` in consumer CI. The package validates positive unique IDs, declared categories, four non-empty normalized-distinct answers, one correct answer, and difficulty `1...3`. Asset-catalog existence, editorial approval, sources, distribution, and app metadata remain consumer-owned checks.
4. Keep question, category, achievement, and `PowerUp` IDs stable. Question IDs are persisted migration identifiers; do not renumber or reuse one for different content.
5. Map legacy data in the app, then submit one complete `PlayerProgressImportRequest` with a stable identifier and source fingerprint. Map each legacy hint to one `.fiftyFifty` credit and each legacy skip to one `.skipQuestion` credit. Never convert those credits to coins.
6. Preserve legacy files. QuizEngine's marker-backed import verifies the destination and prevents duplicate imports, but it never deletes app-owned legacy input.

See [Persistence, upgrades, and troubleshooting](persistence-upgrades-troubleshooting.md) for the schema, recovery, and import-transaction failure contract.
